0. 昨日最后问题回顾｜Spring AI 没有 Agent Loop 吗？

昨日最后一个学习相关问题：“这个springAI没有？”｜语境：追问 Spring AI 是否没有 Agent Loop / Tool Calling Loop。

纠正版：Spring AI 2.0 有官方 Tool Calling Loop。它不是一个名为 AgentLoop 的独立类，而是由 ChatClient Advisor Chain 中的 ToolCallingAdvisor 驱动，ToolCallingManager 执行工具。

ChatClient → ToolCallingAdvisor → ChatModel → Tool Call → ToolCallingManager → Tool Result → 再次调用模型 → 直到不再请求 Tool
昨日纠错：context.addObservation(...) 只是说明 Agent Loop 的伪代码，不是 Spring AI 官方 API。
面试口述版：Spring AI 2.0 有正式 Tool Calling Loop；ToolCallingAdvisor 驱动循环，ToolCallingManager 执行 @Tool/ToolCallback 并把结果重新交给模型。但复杂状态、审批、恢复和业务 Workflow 仍可能需要额外编排。

1. HashMap 和 TreeMap 有什么区别？

《后端高频面试题大集合》JAVASE 核心，第 7 题｜“说下 HashMap、TreeMap 底层结构和使用场景”｜PDF 约第 5～6 页。
类型底层复杂度主要价值
HashMap哈希表 + 链表/红黑树平均 O(1)快速查找
TreeMap红黑树O(log n)按 Key 有序、范围查询
补充/纠错：TreeMap 的价值不是“比 HashMap 查得快”，而是排序与范围查询。
面试口述版：HashMap 适合普通快速查找；TreeMap 根据 Key 排序，适合有序遍历和范围查询。

2. ConcurrentHashMap 为什么比 Hashtable 并发性能高？

《后端高频面试题大集合》JAVASE 核心，第 8 题｜“了解 ConcurrentHashMap 吗？为什么性能比 Hashtable 高”｜PDF 约第 6 页。
JDK 7：Segment + HashEntry
JDK 8+：Node[] + CAS + synchronized
版本纠错：“ConcurrentHashMap 使用分段锁”主要是 JDK 7 的描述；现代 Java 面试应说明 JDK 8+ 已取消 Segment 主体结构。
面试口述版：Hashtable 同步粒度较粗；ConcurrentHashMap 在 JDK 8+ 通过 Node 数组配合 CAS 和 synchronized 控制局部更新，因此并发度更高。

3. Java 泛型是什么？

《后端高频面试题大集合》JAVASE 核心，第 9 题｜“介绍下什么是 java 泛型技术和使用场景”｜PDF 约第 7～8 页。

泛型本质是参数化类型，核心价值是编译期类型安全、减少强制转换、提高 API 复用性。

class Box<T> { T value; }
Box<String> box = new Box<>();
补充：Java 泛型主要通过类型擦除实现；List<String> 也不是 List<Object> 的子类型。
面试口述版：Java 泛型就是参数化类型，最大的价值是把许多类型错误提前到编译期，同时减少强制转换并提高复用性。

Tools@Tool / ToolCallback

5. AI 智能云盘可以做哪些应用？

《AI大模型面试题-基础篇》第 3 题｜“请举例说明 AI 智能化云盘项目中可以开发哪些具体的应用场景”｜PDF 约第 2～3 页。
文件上传 → 解析 → Chunk → Embedding → VectorStore → 检索 → RAG Advisor → ChatClient
工程补充：企业 RAG 必须考虑 ACL。应把 userId、companyId、departmentId、fileId、permission 等放进 metadata，并在检索时按当前用户权限过滤。
面试口述版：AI 智能云盘可以做文档摘要、企业知识库、智能搜索和垂直助手。Spring AI 可用 Document、EmbeddingModel、VectorStore 和 RAG Advisor 实现；企业场景还必须做 metadata + ACL 权限过滤。
