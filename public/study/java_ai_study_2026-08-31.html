昨日最后问题回顾｜JVM Stack 到底是什么？

昨日最后学习追问：“这个好像没讲到”——对应昨日图中出现但未正式展开的 Stack（JVM 虚拟机栈）。

JVM Stack 是线程私有的运行时内存区域。每个 Java 线程都有自己的虚拟机栈；每调用一个 Java 方法，通常会创建一个栈帧压入当前线程的栈，方法结束后再弹出。

线程 A
└── JVM Stack
    ├── methodC() 栈帧  ← 当前执行
    ├── methodB() 栈帧
    └── methodA() 栈帧

methodC() 返回
        ↓
methodC 栈帧弹出
        ↓
继续执行 methodB()

一个栈帧通常包含：局部变量表、操作数栈、动态链接、方法返回相关信息。

public void test() {
    int age = 20;
    User user = new User();
}

当前线程 Stack
└── test() 栈帧
    ├── age = 20
    └── user = 对象引用 ─────────┐
                                │
Heap                            │
└── new User() 对象 ◄───────────┘
易错点：不要说“对象都在 Stack”。基础面试模型里，对象实例主要在 Heap，局部变量和对象引用位于当前方法栈帧中。
面试口述版： JVM 虚拟机栈是线程私有的，每个线程都有自己的栈。Java 方法调用时通常会创建栈帧，保存局部变量表、操作数栈、动态链接和返回信息等；方法调用时入栈，方法结束后出栈。递归过深导致栈帧持续累积时，可能出现 StackOverflowError。

1. String / StringBuffer / StringBuilder

出处：《后端高频面试题大集合》→ JAVASE 核心 → 第 1 题：String/StringBuffer 与 StringBuilder 的区别和使用场景。

原资料内容

  • String 不可变。
  • StringBuilder、StringBuffer 可变。
  • StringBuilder 通常效率更高；StringBuffer 提供同步保证。

当天纠错 / 补充｜Java 9 Compact Strings

Java 9+ 的 String 引入 Compact Strings，核心内部表示从 Java 8 常见的 char[] 转为 byte[] + coder。
字符串典型内部编码存储理解
"Hello"LATIN1约 1 byte / 字符
"你好"UTF16约 2 bytes / UTF-16 code unit
"Hello你好"UTF16整个 String 使用 UTF16 表示

今日追问｜String 不是可以通过 += 改值吗？

纠正：+= 没有修改原 String 对象，而是生成新 String，然后让变量重新指向新对象。

String key = "abc";

key ─────► "abc"

key += "def";

             "abc"       （旧对象没改）
key ─────► "abcdef"      （变量改指向）
面试口述版： String 是不可变对象，StringBuilder 和 StringBuffer 是可变字符串。频繁拼接通常优先 StringBuilder；StringBuffer 用于确有多线程共享可变字符串的场景。Java 9 开始 String 引入 Compact Strings，内部主要是 byte[] 加 coder。String 的 += 不是原地修改，而是生成新 String 后重新赋值。

2. HashMap：数组 + 链表 + 红黑树

出处：《后端高频面试题大集合》→ JAVASE 核心 → 第 2 题：HashMap 底层是数组+链表+红黑树，为什么用这几类结构？

原资料内容

  • 数组负责通过 hash 快速定位 bucket。
  • 链表用于处理哈希冲突。
  • 链表过长时可转红黑树，避免查询退化。

当天纠错 / 补充｜并非达到 8 就一定树化

TREEIFY_THRESHOLD     = 8
UNTREEIFY_THRESHOLD   = 6
MIN_TREEIFY_CAPACITY  = 64

当桶内节点达到树化阈值时，还要看 table.length。容量不足 64 时通常优先扩容。

今日追问①｜这里说的是哪里的容量？

概念含义
capacity底层 table 数组长度，例如 16 / 32 / 64
sizeHashMap 当前实际键值对数量
桶内链表长度某一个 bucket 中挂了多少冲突节点

今日追问②｜它是自动分配的吗？使用时好像不用管？

是。普通业务代码中 HashMap 会自动初始化、扩容、处理链表和树化。通常只需要正常使用 put/get。

new HashMap<>()
  ↓
第一次 put
  ↓
初始化 table
  ↓
元素增加
  ↓
达到扩容条件
  ↓
resize
  ↓
16 → 32 → 64 → 128 → ...

今日追问③｜Key 不一样，也可能装在同一个链表上？

是。这就是 Hash Collision（哈希冲突）：不同 Key 最终可能落到同一个 bucket。
"AAA" ── hash/index ──┐
                      ├──► table[5]
"BBB" ── hash/index ──┘

table[5]
  ├── Node("AAA", 100)
  └── Node("BBB", 200)

get 时先通过 hash 定位 bucket，再通过节点 hash 与 equals() 最终确认具体 Key。

易错点：hashCode/hash 用于快速缩小范围；equals() 用于最终判断逻辑 Key 是否相等。

为什么可变对象做 Key 危险？

User key = new User("Tom");
map.put(key, "value");

key.setName("Jerry"); // 假设 name 参与 hashCode()

// 对象仍在旧 bucket，新的 hash 却可能指向另一个 bucket
map.get(key); // 可能找不到
面试口述版： JDK 8 HashMap 主要由数组、链表和红黑树组成。数组负责通过 hash 快速定位 bucket；不同 Key 可能落到同一个 bucket，因此需要链表或树保存冲突节点。链表达到树化阈值后也不是无条件树化，当 table 容量不足 64 时通常会优先扩容。

3. Java 接口：多继承与方法实现

出处：《后端高频面试题大集合》→ JAVASE 核心 → 第 3 题：java 接口是否支持多继承？接口里面是否可以有方法实现。

Java 类只支持单继承，但接口可以多继承，一个类也可以实现多个接口。Java 8 开始接口可以定义 default 和 static 方法；Java 9 开始还可以定义 private 方法。

interface A {
    default void hello() {
        log();
    }

    private void log() {
        System.out.println("log");
    }
}
面试口述版： Java 的类只支持单继承，但接口支持多继承，一个类也可以实现多个接口。Java 8 开始接口可以定义 default 和 static 方法；Java 9 开始还可以定义 private 方法。若多个接口提供冲突的 default 方法，实现类需要显式覆盖。
