1. 什么是 JVM？常见的 JVM 实现有哪些？

原 PDF：JVM 虚拟机，第 1 题，难度 ★★

核心理解

JVM（Java Virtual Machine）是 Java 程序的运行环境。Java 源代码不会直接交给 CPU 执行，而是先编译成字节码，再由 JVM 执行。

Hello.java
    ↓ javac
Hello.class（字节码）
    ↓
JVM
    ↓
机器指令
    ↓
CPU 执行

所以 JVM 可以理解成：

Java 字节码和具体操作系统、CPU 之间的一层运行环境。

Java 能跨平台，是因为不同系统安装各自对应的 JVM，而同一份 .class 字节码通常无需改变。

容易说错：不是“JVM 跨平台”，而是“Java 字节码跨平台，JVM 本身与平台相关”。

JVM 主要负责什么？

JVM
├── 类加载
├── 内存管理
├── 垃圾回收 GC
├── 字节码执行
└── JIT 即时编译

例如：

User user = new User();
User.class 从哪里来？
        ↓
ClassLoader 类加载

User 类的信息放哪？
        ↓
方法区 / 元空间

new User() 对象放哪？
        ↓
Heap 堆

user 局部变量放哪？
        ↓
当前线程栈帧

对象不用了怎么办？
        ↓
GC

HotSpot 是什么？

HotSpot 是目前最主流的 JVM 实现之一，也是 OpenJDK 中常见的 JVM 实现。

JVM        → 抽象概念 / 规范层面
HotSpot    → 一种具体实现

面试回答模板

JVM 是 Java Virtual Machine，也就是 Java 虚拟机，它负责执行 Java 编译后生成的字节码，同时提供类加载、内存管理、垃圾回收等运行时能力。Java 能跨平台，本质上是同一份字节码可以运行在不同平台对应的 JVM 上。目前常见的 JVM 实现之一是 HotSpot。
AI 补充｜JDK、JRE、JVM：
JDK 可以粗略理解为“开发工具 + Java 运行环境”，JVM 是其中真正负责执行字节码的核心部分。新版本 Java 已不太强调单独安装 JRE，因此面试时掌握层级关系即可。

2. 方法区、永久代、元空间是什么关系？

原 PDF：JVM 第 6 题，难度 ★★★

一句话先记住

方法区是 JVM 规范中的逻辑概念；永久代和元空间是 HotSpot 对方法区的不同实现方式。 
方法区
   ↓ JVM 规范中的概念

永久代 PermGen
   ↓ JDK 8 之前 HotSpot 常见实现

元空间 Metaspace
   ↓ JDK 8 之后 HotSpot 实现

方法区主要放什么？

主要是和“类”相关的元数据信息，例如：

  • 类的结构信息
  • 字段信息
  • 方法信息
  • 运行时常量池等
简化记忆：对象主要在 Heap；类的信息主要在方法区。

永久代以前为什么需要特别注意？

JDK 8 以前，HotSpot 的永久代由 JVM 管理，并且通常会配置相对明确的容量上限，例如：

-XX:PermSize=128m
-XX:MaxPermSize=256m

可以理解为：

永久代初始大小：128MB
永久代最大大小：256MB

如果动态加载的 Class 太多，超过永久代上限，就可能报：

java.lang.OutOfMemoryError: PermGen space
特别好记的点：
即使你配置了 -Xmx4g，也不代表永久代有 4GB。
-Xmx 主要控制 Java Heap，而永久代以前有自己的 -XX:MaxPermSize。 
JDK 7 以前

Heap
└── -Xms / -Xmx

PermGen
└── -XX:PermSize / -XX:MaxPermSize

JDK 8 以后为什么换成 Metaspace？

JDK 8 后，永久代被移除，类元数据主要改放到 Metaspace。Metaspace 主要使用 Native Memory（本地内存），因此扩展更灵活。

JDK 8+

Native Memory
└── Metaspace
注意：使用本地内存 ≠ 永远不会 OOM。
如果不断动态生成或加载 Class，仍然可能出现：
java.lang.OutOfMemoryError: Metaspace

面试回答模板

方法区是 JVM 规范定义的一块逻辑内存区域，主要存储类的元数据、运行时常量池等信息。在 HotSpot 中，JDK 8 之前主要通过永久代实现方法区，JDK 8 之后永久代被移除，改为元空间。元空间主要使用本地内存，因此空间扩展更加灵活，但如果大量动态生成或加载类，同样可能发生 Metaspace OOM。
AI 补充｜和 Spring 的关系：
Spring、CGLIB、动态代理、反射、第三方框架等场景可能动态创建或加载大量 Class。因此线上出现 OutOfMemoryError: Metaspace 时，不应该只盯着 -Xmx，还需要检查类加载数量、ClassLoader 泄漏以及 Metaspace 配置。

3. 什么是类加载？什么是双亲委派？

原 PDF：JVM 第 8 题附近，难度 ★★★★

类加载是什么？

.class 文件不会自动进入 JVM。JVM 需要通过 ClassLoader 找到并加载类信息。

User user = new User();

        ↓

JVM 需要先知道 User 是什么
        ↓
找到 User.class
        ↓
ClassLoader 加载
        ↓
形成 JVM 可以使用的类信息

常见类加载器层级

Bootstrap ClassLoader
        ↑
Platform ClassLoader
        ↑
Application ClassLoader
  • Bootstrap：负责 Java 核心类。
  • Platform：负责 Java 平台相关类。
  • Application：主要加载我们项目自身的 Class 和依赖。

双亲委派是什么？

一个类加载器收到加载请求后，通常不会立即自己加载，而是优先委派给父加载器。

Application ClassLoader
        ↓ 先问父级
Platform ClassLoader
        ↓ 再问父级
Bootstrap ClassLoader
        ↓
父加载器找不到时
        ↓
下层加载器再尝试自己加载
最简单记法：先问爸爸，爸爸不行，我再自己来。

为什么需要双亲委派？

① 避免 Java 核心类被随便替换

这是今天特别值得保留的例子。

假设自己写了一个：

package java.lang;

public class String {
    // 自己伪造一个 String
}

如果 Application ClassLoader 可以直接加载自己的类，那么 Java 核心类体系就可能被应用代码干扰。

双亲委派下，过程变成：

自己定义 java.lang.String
        ↓
Application ClassLoader 收到加载请求
        ↓
先委派给父加载器
        ↓
Platform 再向上委派
        ↓
Bootstrap ClassLoader
        ↓
找到 JDK 自带 java.lang.String
        ↓
加载真正的核心 String
        ↓
应用自定义的同名核心类不会取代它
这个例子要记住：
双亲委派的重要价值之一，就是保护 Java 核心类体系，避免应用代码轻易替换 JDK 核心类。

② 减少重复加载和类型混乱

JVM 判断两个类是不是同一个类，不只看包名和类名，还要看是谁加载它的。

Loader A 加载 com.test.User
Loader B 加载 com.test.User

即使 class 内容相同，
JVM 仍可能认为它们是不同的类型。

也就是说，类的身份可以粗略理解为：

类的完整名称
+
加载它的 ClassLoader

这也是以后理解 Tomcat、插件系统、SPI、热部署、Spring Boot DevTools 等机制的重要基础。

面试回答模板

类加载就是 JVM 通过 ClassLoader 将 .class 字节码加载到运行时环境中的过程。Java 类加载器之间通常采用双亲委派机制，当一个类加载器收到类加载请求时，会优先把请求交给父加载器，父加载器无法加载后，当前加载器再尝试加载。这样一方面可以保护 Java 核心类体系，提高安全性；另一方面也能减少类重复加载和类型混乱。另外，JVM 判断一个类的身份时，不只是看类名，还和加载它的 ClassLoader 有关。

补充：今天图里提到但还没正式展开的 Stack

今天只做最小理解，后续再正式学习。

线程
└── JVM Stack（虚拟机栈）
    ├── 栈帧：methodA()
    ├── 栈帧：methodB()
    └── 栈帧：methodC()

每调用一个 Java 方法，通常会创建一个栈帧并压入当前线程的虚拟机栈；方法执行完后栈帧弹出。

一个栈帧里常见内容：

  • 局部变量表
  • 操作数栈
  • 动态链接
  • 方法返回地址
public void test() {
    int a = 10;
    User user = new User();
}
虚拟机栈
└── test() 栈帧
    ├── a = 10
    └── user = 指向堆中 User 对象的引用

Heap
└── User 对象
今天只记：对象主要在 Heap；方法执行过程和局部变量与 Stack 密切相关。
