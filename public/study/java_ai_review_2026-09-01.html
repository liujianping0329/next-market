今日目标：不增加大量新知识，先把昨日 6 个高频问题真正讲顺，达到能自己口述的程度。

1. 为什么 String 的 += 不代表 String 是可变对象？

String 对象一旦创建，其内容不会被修改。

String s = "abc";
s += "def";

执行后并不是把原来的 "abc" 改成 "abcdef"，而是产生新的 String，然后变量 s 改为指向新对象。

s ──► "abc"

s += "def"

s ──► "abcdef"
      ↑ 新对象

"abc" 本身没有被修改
面试口述版：String 是不可变对象。+= 看起来像修改字符串，实际上是生成新的 String 再把变量重新指向新对象，所以不会破坏 String 的不可变性。

2. 为什么 String 很适合作为 HashMap Key？

HashMap 放入 Key 时，会根据 Key 的 hashCode() 计算它应该进入哪个 bucket。

如果 Key 是可变对象，并且参与 hashCode 的字段之后被修改，就可能出现：

put 时：
key.hashCode() → bucket[5]

修改 key 内容后：
key.hashCode() → bucket[9]

但对象仍然挂在 bucket[5]
get(key) 却会去 bucket[9] 找
→ 可能找不到

String 不可变，因此放入 HashMap 后，其内容、hashCode 语义不会因为对象自身被修改而变化。

面试口述版：String 不可变，作为 Key 后内容不会变化，因此 hashCode 和 equals 的语义稳定，不容易出现 Key 修改后定位到错误 bucket 的问题，所以非常适合作为 HashMap Key。

3. capacity、size、桶内链表长度分别是什么？

概念含义例子
capacityHashMap 底层 table 数组长度16、32、64、128
size整个 HashMap 当前保存的键值对数量map.size() = 20
桶内长度某一个 bucket 中发生冲突后挂了多少节点table[5] 有 8 个 Node
 
table capacity = 16

table[0]
table[1] → A
table[2]
table[3] → B → C → D
...
table[15]

size = 4
table[3] 的桶内长度 = 3
面试口述版：capacity 是底层数组长度，size 是整个 Map 的键值对数量，而桶内链表长度只描述某一个 bucket 内因为哈希冲突形成的节点数量，这三个概念不能混为一谈。

4. 两个不同 Key 为什么可能进入同一个 bucket？get 时怎么找到正确 Key？

HashMap 的 bucket 数量是有限的，而可能出现的 Key 几乎无限，因此不同 Key 最终计算出的数组下标可能相同，这就是哈希冲突。

Key A ── hash/index ──┐
                      ├──► table[5]
Key B ── hash/index ──┘

get(key) 时通常可以理解为两步：

  1. 根据 hash 快速定位 bucket。
  2. 在 bucket 内继续比较节点 hash，并使用 equals() 确认真正的 Key。
记忆：hashCode/hash 负责“缩小范围”，equals() 负责“最终确认”。
面试口述版：不同 Key 可能因为哈希冲突落入同一个 bucket。get 时先利用 hash 定位 bucket，再在桶内结合节点 hash 和 equals 判断，最终找到正确 Key。

5. 链表达到 8 后是否一定树化？

不是。JDK 8 HashMap 中常见的几个关键值：

TREEIFY_THRESHOLD    = 8
UNTREEIFY_THRESHOLD  = 6
MIN_TREEIFY_CAPACITY = 64

当某个 bucket 中节点很多、达到树化条件时，还需要看整个 table 的容量。

  • 桶内节点达到阈值，并且 table 容量至少达到 64：才倾向于树化。
  • table 容量还不到 64：通常优先 resize 扩容，而不是立即变成红黑树。
为什么？容量太小时，冲突可能只是因为 bucket 数量不够。先扩容就可能把原本挤在一起的节点分散到不同 bucket，没有必要马上付出红黑树的复杂度。
面试口述版：链表达到 8 并不代表一定树化。HashMap 还会检查 table 容量；容量不足 64 时通常优先扩容，容量足够且桶内节点达到条件后才会树化。

6. Agent 和单纯 LLM / Tool Calling 有什么区别？

层级核心能力
LLM理解输入并生成文本 / 推理结果
LLM + Tool Calling模型可以选择并调用外部工具
Agent围绕目标进行多步规划、调用工具、观察结果、继续决策，并维护状态直到完成或退出
 
用户目标
   ↓
LLM 判断下一步
   ↓
调用 Tool
   ↓
得到 Observation
   ↓
再次判断
   ↓
继续 Tool / 改计划 / 输出答案
   ↓
完成

因此，Spring AI 中注册一个 @Tool 并让 ChatClient 调用它，属于 Agent 的重要基础能力，但不能仅凭“使用了 Tool Calling”就说已经构建了完整 Agent。

面试口述版：LLM 主要负责理解和生成；Tool Calling 让模型能够调用外部能力；Agent 则是在此基础上围绕目标进行规划、执行、观察和多步迭代，通常还会涉及 Memory、状态管理、失败恢复、退出条件和可观测性。
